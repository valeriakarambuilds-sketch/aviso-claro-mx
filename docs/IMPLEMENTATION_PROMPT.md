## Small features and acceptance criteria

1. Create Next.js/TypeScript with responsive Spanish UI: Evidencia, Borrador, Revision. Persistent visible DEMO - DATOS FICTICIOS banner, trusted-device warning, and explicit AI mode. No database, personal-data forms, file upload, analytics, case persistence, or automatic sending. Select three breach cases and one impersonation/fundraiser route from fictional JSON fixtures.
2. Define strict Zod schemas for scenario IDs, evidence IDs, enums and booleans. Reject extra fields, invalid combinations, malformed JSON, and excessive input size on the server. The server derives the evidence/caption catalog; it never uses a client prompt or arbitrary client prose. Write a pure support checker that maps approved sentence variants to required evidence/status. Unknown is the default; source authenticity is not automatically verified.
3. Implement a catalog of exact Spanish sentences. LLM output is only allowlisted sentence IDs and evidence references, never arbitrary incident prose. Require unknown-impact wording when impact is unknown. Investigation-in-progress is a separate supported fact. Reject unsupported confirmations, invented IDs, false reassurance, omissions, or extra keys. Render each sentence with its source and distinguish structural reference completeness from real verification. Block export on a failed check.
4. Add preparer -> review workflow. Human acknowledgment applies only to the current case/evidence/draft version. Any change or regeneration clears it. Export handler rechecks validity and current approval even if the button is bypassed. Export TXT locally and sanitized print HTML with DOMPurify; normal screen text uses React escaping. Label exports fictional; include no reviewer personal information. This is a demo acknowledgment, not independent authenticated approval. No free-form draft editor in this version.
5. Add server-only Gemini adapter behind environment configuration, with GEMINI_API_KEY and GEMINI_MODEL placeholders only in .env.example. Choose an eligible free-tier model using current official docs; do not enable paid billing. Request structured JSON and independently validate its support. Send only fictional categorical inputs. Add bounded request size, timeout and output; same-origin checks and JSON POST only. Missing key, timeout, quota exhaustion, invalid output, or rejected unsupported output uses catalog fallback labeled IA SIMULADA - PLANTILLA DEMO with the reason. Live validated output is labeled IA REAL - SOLO CASOS FICTICIOS. Do not log request bodies or expose credentials. Do not claim fallback ran a model. Label a rejected attempt clearly even when offering the safe fallback.
6. Implement tests from the packet with Vitest and Playwright. Include unsupported certainty, invented evidence IDs, access vs exfiltration, mandatory unknowns, injection/extra-field rejection, approval reset, stale-version/direct-export bypass, sanitized print output, API errors and mode labels, no persistence, and mobile/keyboard use. Test the support gate independently of model output. Review dependency vulnerabilities and security headers. Do not use real personal data.
